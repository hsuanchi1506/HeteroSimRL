# 離線檢查（沒有 Isaac Lab、沒有 GPU 也能跑）

用最小的替身模組取代 Isaac Lab，載入**官方原封不動的** Factory 原始檔，檢查 `hetero_factory` 的邏輯。替身沒有物理：零件只有被程式寫入位置時才會動，機器人的 IK 被換成「直接把指尖放到目標」。所以這裡抓得到的是程式邏輯的錯，抓不到物理上的問題，那要到 GPU 機器上跑。

## 跑法

需要有 torch 的 Python（不需要 Isaac Lab）：

```bash
python fetch_official.py
python check_cfg.py
python check_env.py
python check_rl_utils.py
python check_grad_probe.py
python check_list_env.py
python check_video.py
```

`fetch_official.py` 會下載 5 個官方程式檔和官方的 rl_games 設定（預設 v2.3.2，和 main 一樣）到 `stubs/isaaclab_tasks/direct/factory/`，這些檔案不放進 repo。`check_rl_utils.py` 另外需要 `gymnasium` 和 `pyyaml`。

## 檢查內容

`check_cfg.py`（也會重新產生 `../TASK_PARAMS.md`）：
- 任務參數表的每個值和手算的一樣
- 任務分配：3 個環境一個任務一個；128、4096 個環境時，三個任務的數量最多差 1，每 3 回合加起來剛好相等
- 聯集場景：8 個零件槽、prim 路徑不重複、零件設定和官方一樣、停放位置互相隔開
- 輸入維度：策略 22、critic 46

`check_env.py`：
- **和官方一致**：Homo 模式下，用同一個亂數種子，三個任務各自和官方 `FactoryEnv` 比。重設後的零件位置和方向、觀測、12 步的獎勵和動作都完全一樣
- **Hetero 的分流**：7 個環境，每個環境自己任務的零件在桌上，其他停放；只有齒輪環境有兩個固定齒輪；夾爪依任務張開；只有螺帽環境做單向旋轉
- **一整個回合**：所有環境一起在官方螺帽的回合長度結束，下一回合多出來的那個環境換任務，零件跟著換
- **成功判定**：零件放到目標時三個任務都成功；手的角度不對時只有螺帽失敗；高 0.9 mm 時插銷、齒輪成功、螺帽失敗
- **Homo 換任務**（照 rl_games 的節奏：每輪跑 H 步再記錄統計）：
  - `rollout` 模式，block 1 和 2：每一輪的樣本都只有一種任務，依插銷、齒輪、螺帽輪流；被切斷的回合標成 truncated，長度剛好是 block × H 步
  - 回合在 block 中間自然結束時，任務不變，換任務仍然落在 block 的最後一步
  - `episode` 模式：每個完整回合換一次任務，沒有回合被切斷，但有幾輪的資料混到兩種任務
  - Hetero：每一輪三個任務的樣本比例固定

`check_rl_utils.py`：
- minibatch 修正：3 個環境時 512 改成 384（PPO 和 critic 各一處），128、4096 個環境保持官方的 512
- 用總步數換算訓練輪數
- `env.step` 計時、每輪一行的紀錄（每個任務的數值有帶進去、每個環境的向量不會被記）
- 沒有 NVML 時 GPU 取樣不會讓程式當掉
- 兩個訓練腳本至少能編譯

- rl_games 每輪會呼叫兩次記錄統計，`metrics.jsonl` 仍然一輪只寫一行；梯度分析的摘要和扣掉分析時間的牆鐘時間有寫進去

`check_grad_probe.py`（用一個和 rl_games 同樣結構的小 LSTM 策略，不需要 rl_games）：
- 每個任務的梯度和「全部樣本一次算、只取該任務」的結果一樣，不管分段大小是 1、3 還是全部
- 整體梯度等於各任務梯度依樣本數的加權平均
- 沒有副作用：全域亂數、輸入正規化的統計值和模式、參數的 `.grad`、模型輸出都沒變
- 量的時機：第 1、2 輪，之後第 10、11、20、21 輪……；相鄰的兩次有標記
- 參數變化每輪都記；只有一個任務的 rollout（Homo）沒有任務之間的夾角

`check_list_env.py`（大 list 版本；假模擬器故意把零件槽的資料列倒過來排）：
- 每個零件槽只存在它任務的環境裡，機器人在每個環境，沒有東西被停放
- 和聯集場景比：零件位置、觀測、12 步的獎勵都一樣（interleaved 和 blocked 兩種排法）
- 每個環境讀到的零件，是對照表指到的那一列；寫入不會超出零件槽的範圍；小齒輪坐在自己的齒輪底座上
- 一整個回合後重設（傳「全部」）沒問題，任務不變
- 不接受 Homo；每輪樣本數固定

這套檢查測不到的：Hydra 載入設定、rl_games 真正的訓練迴圈、Isaac Lab 的包裝層、Isaac Lab 能不能接受資料列數比環境數少的 `Articulation`。這些要在 GPU 機器上第一次跑時確認。

`check_video.py`：
- 格子拼圖：每個環境在對的位置，成功的才有綠框，有標籤，缺的格子補黑
- PNG 的備用寫法；有 `imageio-ffmpeg` 時也測 mp4（這台筆電沒有，所以跳過）
- 錄影腳本放攝影機的時機：聯集場景在複製之前，大 list 場景在每個環境建好之後，各只放一次
- 錄影腳本能編譯

## 2026-10-04 的結果

六個檔案都是 0 個失敗。
